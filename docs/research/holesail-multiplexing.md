# Holesail 2.4.1：单连接是否可复用为命名多服务？

**核验范围。** 以 Holesail `2.4.1` tag（commit [`64226f3a317da6c3eee543ed50f51adce155612a`](https://github.com/holesail/holesail/commit/64226f3a317da6c3eee543ed50f51adce155612a)）及其官方文档仓库 commit [`0734a81df01be9e98d2cd4c91350e06bf415c6bf`](https://github.com/holesail/docs/commit/0734a81df01be9e98d2cd4c91350e06bf415c6bf) 检查 CLI、连接构造、服务端/客户端和 key 语义。该 tag 的 `package.json` 也确认版本为 2.4.1（[L1-L5](https://github.com/holesail/holesail/blob/64226f3a317da6c3eee543ed50f51adce155612a/package.json#L1-L5)）。

## 证据

1. **用户模型是一个端口对应一个 server/key。** 官方 overview 的流程是 `holesail --live 8080`，然后用一个 `<key>` 连接；明确说“port from device 1”在另一端可用（[overview L3-L35](https://github.com/holesail/docs/blob/0734a81df01be9e98d2cd4c91350e06bf415c6bf/usage-guide/overview.md#L3-L35)）。server 指南将 `--live` 定义为要 expose 的单个 `PORT`，并给出单端口示例（[server guide L3-L46](https://github.com/holesail/docs/blob/0734a81df01be9e98d2cd4c91350e06bf415c6bf/usage-guide/start-a-holesail-server.md#L3-L46)）。client 指南同样只有一个 `<KEY>` 和一个本地 `--port`（[client guide L3-L45](https://github.com/holesail/docs/blob/0734a81df01be9e98d2cd4c91350e06bf415c6bf/usage-guide/connect-to-holesail-server.md#L3-L45)）。

2. **CLI/API 没有服务名或服务表。** 2.4.1 CLI 的 `--live` 分支只构造一个 `Holesail({ server: true, port: argv.live, host, key, ... })`；连接分支只构造一个 `Holesail({ client: true, port, host, key, ... })`（[CLI L45-L78](https://github.com/holesail/holesail/blob/64226f3a317da6c3eee543ed50f51adce155612a/src/bin/holesail.mjs#L45-L78)）。核心连接只把单个 `port/host/seed/udp` 传给 `server.start()`，或把单个 `port/host/udp` 传给 `client.connect()`（[index.js L110-L127](https://github.com/holesail/holesail/blob/64226f3a317da6c3eee543ed50f51adce155612a/src/index.js#L110-L127)）。

3. **key 对应的 DHT 元数据也只有一个目标端口。** `holesail-server` `2.4.0`（commit [`493db37327494a3a789a2adbec661bec1a2e1289`](https://github.com/holesail/holesail-server/commit/493db37327494a3a789a2adbec661bec1a2e1289)）把 `{ host, udp, port }` 写入 DHT（[L82-L97](https://github.com/holesail/holesail-server/blob/493db37327494a3a789a2adbec661bec1a2e1289/index.js#L82-L97)），不是服务名到端口的 registry。每个收到的 DHT/HyperDHT 连接都按这个同一个 `args.port/args.host` pipe 到本地服务（[L52-L70](https://github.com/holesail/holesail-server/blob/493db37327494a3a789a2adbec661bec1a2e1289/index.js#L52-L70)、[L100-L121](https://github.com/holesail/holesail-server/blob/493db37327494a3a789a2adbec661bec1a2e1289/index.js#L100-L121)）。

4. **确有“多连接”，但不是多服务复用。** `holesail-client` `2.3.0`（commit [`81eb657f54e63b5ffe5dd4fe6c058fafa599e889`](https://github.com/holesail/holesail-client/commit/81eb657f54e63b5ffe5dd4fe6c058fafa599e889)）监听一个本地 TCP 端口；每个本地连接调用一次 `this.dht.connect(this.publicKey, { reusableSocket: true })`（[L22-L58](https://github.com/holesail/holesail-client/blob/81eb657f54e63b5ffe5dd4fe6c058fafa599e889/index.js#L22-L58)）。底层 `@holesail/hyper-cmd-lib-net` 的 `createTcpProxy` 对每个本地 socket 调用 piper，而 piper 只是双向复制 byte stream（[commit `e4474d5`](https://github.com/holesail/hyper-cmd-lib-net/commit/e4474d57c951936959bfc36912e6bbf94ae849e1)：[L5-L70](https://github.com/holesail/hyper-cmd-lib-net/blob/e4474d57c951936959bfc36912e6bbf94ae849e1/index.js#L5-L70)、[L246-L265](https://github.com/holesail/hyper-cmd-lib-net/blob/e4474d57c951936959bfc36912e6bbf94ae849e1/index.js#L246-L265)）。`reusableSocket` 可能涉及传输层 socket 复用；它没有传递 service name，也没有按名称选择不同目标。UDP 的 framing 也只是按客户端地址和长度分流（[L268-L315](https://github.com/holesail/hyper-cmd-lib-net/blob/e4474d57c951936959bfc36912e6bbf94ae849e1/index.js#L268-L315)），不是应用层命名服务 multiplexing。

5. **认证 key 是 tunnel/endpoint 级别。** 官方术语说明自定义 key 生成 keypair 并用于 DHT 地址和认证；私有模式要求 client/server 使用同一 private key，public 模式则没有 key authentication（[private/public L12-L22](https://github.com/holesail/docs/blob/0734a81df01be9e98d2cd4c91350e06bf415c6bf/terminology/private-vs-public-connection-keys.md#L12-L22)、[L30-L41](https://github.com/holesail/docs/blob/0734a81df01be9e98d2cd4c91350e06bf415c6bf/terminology/private-vs-public-connection-keys.md#L30-L41)）。这说明 key 是找到/授权一个 Holesail server 的凭据，不是包含多个命名服务的 capability manifest。

## 结论

**否：在 2.4.1 的文档和实现中，没有类似 Kepos 的“一个 peer link/一个 authenticated key，按名称选择多个独立服务”的用户能力。** 更准确的模型是：**一次 server invocation 暴露一个本地端口；一个 key 指向该端口；client invocation 在本地再监听一个端口。** 同一个 tunnel 可以承载该端口上的多个 TCP 连接（以及实现内部可能的 socket 复用），但这些是同一服务的并发连接，不是多个 named services。要分享独立服务，应分别启动端口 tunnel，并分别处理其 key；不能靠一个 Holesail link 在应用层选择服务。

## 对 Kepos 网页比较的核对

当前仓库网页比较 commit [`eaf77289f0754539c0ef7b6965e7292d74a39a17`](https://github.com/LamplitIsles/kepos/commit/eaf77289f0754539c0ef7b6965e7292d74a39a17) 的表格写的是：Kepos 的 named services “share one outer connection”，而 Holesail 是“**The documented quickstart is one local port per tunnel**”（[index.html L530-L533](https://github.com/LamplitIsles/kepos/blob/eaf77289f0754539c0ef7b6965e7292d74a39a17/apps/web/docs/index.html#L530-L533)）。这句话**准确且克制**：它没有仅凭 quickstart 宣称数学意义上的“不可能”，而是描述文档模型；CLI、DHT 单端口元数据和 pipe 构造进一步支持该比较。网页随后称 Holesail 为 quick port tunnel（[L572-L581](https://github.com/LamplitIsles/kepos/blob/eaf77289f0754539c0ef7b6965e7292d74a39a17/apps/web/docs/index.html#L572-L581)），与上述核验一致。
