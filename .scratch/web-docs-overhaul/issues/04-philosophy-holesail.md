# 04 — Product philosophy and Holesail comparison

**What to build:** Explain why Kepos preserves mature self-hosted applications while making their access channels P2P, and help readers choose accurately between Kepos's service-distribution model and Holesail's port-oriented tunnel workflow.

**Blocked by:** 02 — Subscriber documentation journey.

Status: completed

- [x] The landing page concisely communicates “keep mature applications, change service distribution, preserve their client experience” without claiming that each application protocol becomes P2P.
- [x] The docs explain how existing browsers, media clients, Git clients, and SSH use ordinary local addresses while Kepos changes the authenticated distribution channel.
- [x] The Holesail comparison cites current official sources and acknowledges its direct encrypted P2P model, connection key or QR workflow, and TCP and UDP support.
- [x] The comparison accurately distinguishes Kepos's persistent device relationship, named registry, separate identities, publisher pinning, allowlists, multiple service channels, native presentation, and current TCP-only boundary.
- [x] Both products are presented as fits for different needs without unsupported claims, affiliation implications, benchmarks, or adversarial wording.
